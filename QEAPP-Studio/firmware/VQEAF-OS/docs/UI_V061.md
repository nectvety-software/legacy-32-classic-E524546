# Symbian S3 OS v0.6.1 UI / Rendering Notes

Target: ST7789 portrait **240 x 320** on ESP32-S3 N16R8. The visual reference is classic Nokia/Symbian S60: warm status/title chrome, dark content lists, compact pixel icons and a three-part softkey bar.

## Geometry

- Title/status bar: `y=0..29` (30 px)
- Content starts: `y=31`
- Softkey/navbar: `y=296..319` (24 px)
- Standard list row: 42 px, up to 6 rows
- Launcher grid: 3 columns, 80 px cells; 3 rows
- Procedural icon box: 28 x 28 px; inner glyph remains deliberately pixelated
- Font2: titlebar, softkeys, primary list labels
- Font1: metadata, RSSI/path/status text and compact hints

## Anti-flicker contract

Normal button navigation must not call `fillScreen()` or blank the content area. The renderer follows these rules:

1. `SymbianUI::clear()` is reserved for boot/theme palette changes.
2. Screen changes use `clearContent()` while preserving title/navbar redraw caches.
3. D-pad selection changes repaint only the old and new item when the viewport does not scroll.
4. If scrolling changes the list offset, only the visible content rows are repainted; the LCD is never blanked first.
5. Title/status chrome is cached and only its clock box is touched when the minute changes.
6. Softkeys are cached and skipped when labels are unchanged.
7. Idle/Home and Lock update only the clock/focus regions during periodic refresh.
8. The text keyboard clears content once on open, then redraws controls in place.
9. Transitions use a thin accent sweep instead of a black full-screen wipe.

## Memory policy

The UI uses TFT primitives directly and intentionally has **no 240x320 framebuffer**. This avoids a ~150 KiB RGB565 frame allocation. v0.6.1 also bounds scan/list caches, removes Font4, reduces audio DMA/work buffers, avoids the Collection temporary file array, and deinitializes NimBLE after a scan because the current BLE app does not keep a connection alive.

Large feature additions should prefer bounded caches, streaming from microSD, and PSRAM only when an operation genuinely requires a large buffer. Do not introduce a permanent full-screen sprite merely to hide flicker; use dirty-region rendering first.
